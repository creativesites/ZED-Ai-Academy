# Sign-up flow: trainers and students

A trainer must be able to go from the landing page to a working academy, a first course and invited students in a few minutes, with no help.

## Source of truth

- **Supabase owns academies and roles.** `companies` (academy, slug, owner `admin_id`, staff code), `company_members` (role per academy) and `profiles` (platform role, onboarding flag) decide what a person can do.
- **Clerk only authenticates.** A Clerk organization is created for each academy, and its id is `companies.id`. Organizations mirror membership for convenience. The app never reads a role or a slug from Clerk to make a decision.
- **The Clerk webhook only inserts what is missing** (`src/app/api/webhooks/clerk/route.ts`):
  - `organization.created` inserts the academy row if it is missing, with a slug generated by the database.
  - `organization.updated` syncs the name and logo, never the slug.
  - Membership events are insert-only (`ignoreDuplicates`).
  - `user.*` events sync name, email and avatar, never the role.
- **Slugs are generated by the database** (`src/lib/tenants/slug.ts`): unique, never a reserved name (`www`, `api`, `admin`, `join`, ...), with `-2`, `-3`, ... added on a collision.
- **Roles never go down.** `ensureTenantMembership` keeps the higher role, onboarding keeps an existing profile role, and a teacher role always needs the academy's staff code.
- **Routing hints are not permissions.** The sign-up URL (`role`, `tenant`, `code`, `redirect_url`) and Clerk `unsafeMetadata` (`signupRole`, `signupTenant`) only decide where a person goes next. The server checks every grant again.

## Trainer flow

1. On the landing page, **Launch Your Academy** goes to `/sign-up?role=company_admin`.
2. The trainer signs up with email or Google. Clerk then sends them to `/launch-your-academy`. An existing account that signs in from this screen also goes there.
3. `/launch-your-academy` shows one form, "Name your academy": a name, plus an optional tagline that becomes the hero subtitle. Submitting calls the `createAcademy` server action (`src/actions/academy.ts`), which:
   - returns the academy the user already owns instead of creating a second one;
   - reuses an organization the user created earlier that never got an academy row (for example after a double click or a closed tab);
   - otherwise creates the Clerk organization (`createdBy` = the user) and the `companies` row (active, DB slug, 6-digit staff code);
   - creates the owner's `company_admin` membership and updates the profile: role `company_admin` (a `super_admin` stays one), `onboarding_completed`, `company_id`, and the name from Clerk.
4. The browser sets the new organization as active, then opens `/academy/{slug}/admin?welcome=1`.
5. The admin hub shows a **Get started** checklist. It appears after launch, and until a course is published. Each step's completion is computed from data:
   - logo and colour (links to the site settings);
   - create the first course (opens the builder at `/creator/courses/{id}`);
   - publish it;
   - invite students, with the join link, a **Copy link** button and **Share on WhatsApp**.
6. If the tab is closed before step 3, signing in again resumes at `/launch-your-academy`: `/after-sign-in` reads the `signupRole` hint.

A signed-in user who opens `/launch-your-academy` and already owns an academy goes straight to its admin hub. `/onboarding?role=company_admin` redirects to `/launch-your-academy`.

## Student flow (invite link `/i/{code}`) — the main path

Most people who sign up are students of an academy that already exists. They never choose an academy: the link decides it. Students never see a list of academies anywhere in sign-up or onboarding.

**Invite links** live in `academy_invites` (`supabase/migrations/20261104000000_academy_invites.sql`). Each link has an 8-character code (alphabet `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, generated with `crypto.randomInt`), a label, a role (`learner` or `teacher`), courses, an optional class group, optional max uses and expiry, and can be revoked. Every academy gets a default "General" student link the first time the admin hub or the Students page needs it. Revoking the default link replaces it with a new one. The tables are server-only (no anon or authenticated grants).

1. The academy shares `https://<host>/i/{code}` from **Admin → Students** or the **Get started** checklist (Copy or WhatsApp). The host is the one the admin is using, so links work on previews, academy subdomains (`https://{slug}.<root>/i/{code}`) and custom domains.
2. `/i/{code}` is public. It shows the academy's logo, name and colour, the courses and group the link includes, and the next live class (Lusaka time). It never mentions another academy. A wrong, revoked, expired or full link shows a friendly message and nothing else.
3. **Signed out:** **Create my account** goes to `/sign-up?role=student&invite={code}`. The page skips the role chooser and says "Create your account to join {Academy}" (the name is looked up on the server). Clerk then sends the new account to `/onboarding?invite={code}`.
4. **Onboarding** asks only "What's your name?". It skips even that when Clerk already has the name (for example Google). It then saves the profile, marks onboarding complete and calls the invite acceptance. The student lands in `/academy/{slug}/classroom`, a member of the academy, enrolled in the link's courses and in its class group.
5. **I already have an account** goes to `/sign-in?invite={code}` and comes back to `/i/{code}`. **Signed in:** one button, **Join {Academy}**, calls `acceptInvite(code)` and opens the classroom.

`acceptInvite(code)` (`src/actions/invites.ts`, logic in `src/lib/tenants/invites-server.ts`) is idempotent:

- It validates the link and the academy.
- It refuses a person the academy removed (membership `deactivated`).
- It counts one use per person atomically (`redeem_academy_invite()`, which respects `max_uses`, `expires_at` and `revoked_at`). Tapping twice never counts twice.
- It calls `ensureTenantMembership` (never downgrades a role, sets `profiles.company_id` if empty).
- For students, it creates free, active enrollments with `source = 'academy_invite'` and no order. An existing active enrollment is left alone, one awaiting payment becomes active, and a revoked one stays revoked.
- It adds the student to the link's class group.
- **Teacher links** (`role = 'teacher'`) are the staff authorization themselves: the code is secret, made by an admin and revocable. They only work if the creator is still the academy's `company_admin` (or the owner, or a super admin). Only admins can create them.

**Admin → Students** (`/academy/{slug}/admin/students`):

- Admins and teachers see the invite links and the academy's students.
- Teachers can share links and create student links.
- Only admins can create teacher links, revoke links, remove a student (the membership is deactivated after a confirm; the profile is kept) or add a student to a course for free.
- There is no QR code yet: no QR library is installed.

If a resume is needed (tab closed after sign-up), Clerk `unsafeMetadata.signupInvite` sends the person back to `/onboarding?invite={code}`.

## Student flow (academy join page, still supported)

1. The trainer shares `https://<site>/academy/{slug}/join`. On an academy subdomain, the link is `https://{slug}.<root>/join`, which is also public.
2. A signed-out student taps **Create Account to Join** and goes to `/sign-up?role=student&tenant={slug}`.
3. After sign-up, the student goes to `/onboarding?role=student&tenant={slug}`. They confirm their name, which is pre-filled, and tap **Start Learning**. This creates the learner membership in that academy only (no global onboarding course) and lands them in `/academy/{slug}/classroom`.
4. An existing account uses **Already have an account? Sign in**. After sign-in it goes through `/academy/{slug}/join`, which adds the learner membership and opens the classroom.

## Teacher flow (staff link)

1. The staff link is `/academy/{slug}/join?role=teacher&code=XXXXXX`. Admin → Staff shows the code.
2. Create account → `/sign-up?role=teacher&tenant={slug}&code=XXXXXX` → `/onboarding?role=teacher&tenant={slug}&code=XXXXXX`, with the code pre-filled. The code is checked, then the teacher membership is created and the teacher lands in `/academy/{slug}/admin`.
3. Teachers can open the academy's courses in the builder (`/creator/courses/{id}`). Access is decided by `company_members`, not `profiles.role`.

## Redirect rules (`src/lib/auth/signup-flow.ts`, `src/proxy.ts`)

- When a signed-in user opens exactly `/sign-in` or `/sign-up`, the proxy sends them on and keeps the intent: `invite={code}` → `/i/{code}`, `role=company_admin` → `/launch-your-academy`, an academy slug → its join page, otherwise `/after-sign-in?redirect_url=...`.
- An `invite` code wins over `role` and `tenant`: a new account goes to `/onboarding?invite={code}`, an existing one to `/i/{code}`.
- `/i/{code}` is public, and on an academy subdomain it is served as is (not rewritten into the academy).
- Clerk sub-paths (`/sign-up/sso-callback`, `/sign-up/verify-email-address`, `/sign-in/factor-one`, ...) are never interrupted.
- Return paths must be same-site paths. Absolute URLs are reduced to their path.

## Clerk dashboard settings to check

- **Organizations enabled.** The app creates them with the backend API.
- **Personal accounts allowed / organization membership not required.** If membership is required, Clerk shows its own "choose organization" step after sign-up, before our launch page.
- **Organization membership limit** high enough for a class (at least 50), or unlimited. Each student and teacher is added to the organization.
- **Organization creation limit per user**: at least 1. `createAcademy` never makes a second one for the same owner.
- **Organization slugs**: either setting works. If slugs are required, `createAcademy` retries with a generated slug. The app never uses it.
- **Webhook** subscribed to `user.*`, `organization.*` and `organizationMembership.*`, with `CLERK_WEBHOOK_SECRET` set in Vercel.
- **Google** social connection enabled for the Google tests below.

## Manual test script (Vercel preview)

Use fresh accounts. Use a private window for each person, and Gmail "+" addresses for email sign-ups. The founder's own account may already own the platform academy, so do not use it for these tests.

1. **Trainer, email**
   1. Open the preview home page and tap **Launch Your Academy**. Expect the "Create your academy owner account" sign-up.
   2. Sign up with email and enter the code. Expect "Name your academy".
   3. Enter "Test ICT Academy" and a tagline, then tap **Create my academy**. Expect the loading text, then the admin hub with "Welcome! Test ICT Academy is live." and 0 of 4 done.
   4. Tap **Create my academy** twice quickly on a second attempt, or reload `/launch-your-academy`. Expect no second academy: you land in the same admin hub.
   5. Open `/academy/test-ict-academy`. Expect no "4.9/5", "95%" or "10k+" anywhere.
2. **Trainer, Google**
   1. In a new private window, tap **Launch Your Academy**, then **Continue with Google**. Expect "Name your academy" with no other screens.
   2. Finish as in test 1. Then sign out, and from `/sign-up?role=company_admin` choose Google again. Expect to land in your existing academy.
3. **Resume after closing the tab**
   1. In a new private window, sign up as a trainer (email). When "Name your academy" appears, close the window.
   2. Open the site again and sign in. Expect "Name your academy" again, not the student dashboard or the onboarding chooser.
4. **First course**
   1. In the checklist, tap **Create a course** and fill in the form. Expect the course builder (`/creator/courses/...`), not a 404.
   2. Add a module, a lesson with one content block, a description, a category and a level. Then publish.
   3. Return to the admin hub. Expect "create" and "publish" ticked. The checklist disappears on the next visit without `?welcome=1`.
5. **Student joins via the link while signed out**
   1. Copy the join link from the checklist, or use **Share on WhatsApp** and open it on a phone.
   2. In a new private window, open the link and tap **Create Account to Join**. Sign up, then confirm your name. Expect the academy classroom.
   3. Back in the admin hub, expect "invite your students" ticked and the student count at 1.
   4. Repeat with an existing account through **Already have an account? Sign in**. Expect the classroom directly.
6. **Teacher joins via the staff link**
   1. In Admin → Staff, copy the staff invite link (`.../join?role=teacher&code=...`).
   2. In a new private window, open it and tap **Create Account to Join**. Sign up. Expect onboarding with the staff code filled in. Tap **Join Academy Staff**. Expect the academy admin hub.
   3. Open one of the academy's courses (Admin → Courses). Expect the course builder to open and edits to save.
   4. Try the staff link with a wrong code. Expect "Invalid staff access code".
7. **Student invite link (main path).** Apply `supabase/migrations/20261104000000_academy_invites.sql` first. You need the academy from test 1, with a published course and one live class on the timetable.
   1. As the trainer, open **Admin → Students** (`/academy/{slug}/admin/students`). Expect "Your academy link" (`.../i/XXXXXXXX`).
   2. Tap **New invite link**. Name it "ICT Cohort Nov", tick the course, tap **Create group**, name it "Evening class", set max uses to 2, and keep expiry at Never. Tap **Create link**. Expect the new link in the list as Active, Used 0 / 2.
   3. Tap **WhatsApp** on it and send it to a phone, or copy it.
   4. On the phone, in a private tab (signed out), open the link. Expect:
      - the academy's logo, name and colour;
      - "You've been invited to join {Academy}";
      - the course, "Evening class" and the next live class;
      - no other academy anywhere.
   5. Tap **Create my account**. Expect "Create your account to join {Academy}", with no role chooser. Sign up with email and enter the code.
   6. Expect "What's your name?" (or nothing, with Google). Enter a name and tap **Start Learning**. Expect the academy classroom. Open the course: it is enrolled, and no payment was asked.
   7. Back on the trainer's Students page, expect the student with the course and "Evening class", and the link at Used 1 / 2.
   8. As a second student, with an account that already exists and is signed in, open the same link. Expect a single **Join {Academy}** button. Tap it, and expect the classroom with the course enrolled. Tap back and **Open {Academy}** again: the link stays at 2 / 2, not 3.
   9. As a third person, open the link. Expect "This invite link is full" and no academy list.
   10. Revoke the link. Open it again. Expect "This invite link has been turned off".
   11. Remove the first student (**Remove**, then confirm). Signed in as that student, open the academy's default link and tap Join. Expect "Your access to {Academy} was removed".
   12. On an academy subdomain (`https://{slug}.<root>/i/{code}`), repeat steps 4 and 5. Expect the same page, and sign-up continuing on the main domain.
